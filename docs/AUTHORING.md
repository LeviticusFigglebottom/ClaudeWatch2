# Authoring Guide — Heroes, Maps, VFX

This is the contract every content author (human or agent) works against. Runtime code never
changes to add content; if you find yourself editing `src/abilities/Ability.gd` or `SimWorld.gd`
to make a hero work, stop and add a hero-local behavior/effect instead.

## Repository shape

```
data/heroes/<id>.tres         generated by tools/build_data.tscn from tools/authoring/heroes/<id>.gd
data/maps/<id>.tres           hand-written MapData (points at the map scene)
data/modes/<id>.tres          ModeData
src/heroes/abilities/*.gd     AbilityBehavior subclasses (hero-unique ability logic)
src/heroes/behaviors/*.gd     HeroBehavior subclasses (hero-unique passives / resources)
src/heroes/deployables/*.gd   Deployable subclasses (turrets, walls, totems...)
src/vfx/hero_vfx/<id>_vfx.gd  optional VFX / deployable-visual recipes for one hero
src/maps/<id>/<Map>.gd+.tscn  code-authored map (extends MapBuilder)
docs/heroes/<id>.md           design notes, counter-web, tuning rationale
docs/maps/<id>.md             place, mood, lanes, timings
```

Validate with `tools/check.sh <map> <mode> <ticks>` (serialized through a lock; run it, read the
output, fix every `SCRIPT ERROR`). Never run the raw Godot binary in parallel with another author.

## Heroes

A hero builder is a script with `static func build() -> HeroData` (see `tools/authoring/heroes/vesper.gd`).
Use `HeroAuthor` helpers. Rules:

- **Ids**: hero id lowercase (`ballast`), ability ids `<hero>_<name>`, status ids `<hero>_<name>` or a
  shared generic (`revealed_lantern`). Status ids must be globally unique.
- **Slots**: `primary` (HOLD weapon or CHANNEL beam), `secondary` (alt-fire / scope / second weapon),
  `ability_1`, `ability_2`, optional `ability_3`, `ultimate`. Quick melee is automatic.
- **Composition first**: build from effects in `src/abilities/effects/` (`HitscanEffect`,
  `ProjectileEffect`, `MeleeEffect`, `BeamEffect` (tick_effects), `AreaEffect`, `HealEffect`,
  `DashEffect`, `KnockbackEffect`, `TeleportEffect`, `DeployEffect`, `ApplyStatusEffect`,
  `CleanseEffect`, `ResourceEffect`). Effects have `delay`. Reach for an `AbilityBehavior` script
  only for mechanics no effect expresses (position swaps, grapples, transforms, resource kits).
- **Behaviors** (`extends AbilityBehavior`): hooks `can_activate`, `on_activate`, `on_fire`,
  `on_tick`, `on_end`, `on_button_released`, `wants_movement_control` + `modify_velocity`.
  They run on the server AND the predicting client: gate authoritative changes with `ctx.is_server`.
  Movement changes (velocity, position) are fine on both sides (that is what prediction is).
- **Hero passives** (`extends HeroBehavior`): `on_tick`, `on_damage_dealt/taken`, `on_kill`,
  `on_death`, `modify_outgoing_damage(ev)`, `modify_incoming_damage(ev)`. Set `hero.hero_script`.
  Hero resources: `hero_resource_name/max/regen`; abilities can cost it (`Cost.HERO_RESOURCE`).
- **Deployables** (`extends Deployable`): `step(dt)`, `damage()`, `absorb()`, `on_destroyed()`,
  optional `on_placed()`. Barrier walls that block shots must add a `StaticBody3D` child on layer
  `RF.barrier_layer(team)` and set `set_meta("deployable", self)` on that body; see
  `src/heroes/deployables/BarrierWall.gd` once it exists (Cathedral) for the pattern.
- **Presentation**: fill `AbilityPresentation` for every ability: `sound_fire/tail/cast/loop/end`,
  `tracer_style` (`bullet|bolt|beam|arc|shell`), `tracer_color`, `muzzle_vfx`, `impact_vfx`,
  `cast_vfx`, `loop_vfx`, camera kick/shake/viewmodel kick (`HeroAuthor.feel`). Sound ids are
  `<hero>_<ability>_<verb>`; the audio pass synthesizes every id referenced by data. Ult stingers:
  `hero.audio.ult_stinger` / `ult_stinger_enemy`, `presentation.voice_line(_enemy)`.
- **Visual identity**: `HeroVisualData` — `build`, `height`, `head` shape, `extras` (silhouette
  pieces), palette, `weapon_style` (`rifle cannon staff blades launcher pistols bow gauntlet orb
  mortar shield_mace lantern harpoon`), `stance`, `silhouette_notes`. Two heroes must not share
  the same (build, head, weapon_style) triple.
- **AI**: fill `AIHeroProfile` and every ability's `AbilityAIHints` (`intent`, ranges,
  `needs_enemies_in_radius`, `use_when_health_below`, `target_ally`, `combo_tags`). Bots use
  nothing else. `ult_style`: `engage | counter | save | zone | combo_enabler | combo_payoff`.
- **Design fields**: `counters`, `countered_by`, `synergies`, `unique_mechanic`, `tagline`,
  `lore`, `playstyle`, `difficulty`.
- **Numbers**: 5v5, TTK on a 200 hp target from full ~1.0–1.6 s for strikers at ideal range; ults
  cost 1500–2100 charge (1 charge ≈ 1 damage/heal; +2.25/s passive); cooldowns 6–14 s.

Validation for a hero: `tools/check.sh test_range control 1800` must show the hero in the status
table with kills/deaths accumulating and no SCRIPT ERROR. Lock a match to your hero with the
console: `map test_range control 9` then read `status`. Bots pick heroes by role automatically.

## Maps

A map is `src/maps/<id>/<Name>.gd` extending `MapBuilder`, with a one-node `.tscn` wrapper (see
`src/maps/test_range/`). In `build()`:

- `setup_environment(hdri, sun_dir, sun_color, sun_energy, ambient, fog_color, fog_density, sky_tint, exposure)`.
  HDRIs available in `assets/hdri/` (Poly Haven, CC0): `venice_dawn_2`, `stierberg_sunrise`,
  `kloofendal_48d_partly_cloudy_puresky`, `syferfontein_1d_clear_puresky`, `rooftop_night`,
  `vignaioli_night`, `misty_pines`, `kloofendal_misty_morning`, `small_hangar_01`, `qwantani_dusk_2`.
- Geometry: `block(pos, size, mat, yaw)`, `floor_slab`, `wall(a, b, h, t, mat)`, `ramp`, `stairs`,
  `deco(mesh, pos, mat)`, `prop("kit/model.glb", pos, yaw, scale)`, `point_light`, `spot_light`.
  `pos` of a block is the center of its base. Everything through `block/wall/ramp/stairs/prop`
  gets collision and is navmesh source geometry.
- Materials: `mat(&"id", tint, uv_scale)`; ids in `assets/textures/` (ambientCG, CC0) plus
  procedural fallbacks: concrete plaster bricks metal metal_plates painted_metal corrugated wood
  planks roof_tiles cobble paving sand snow rock moss grass tiles marble fabric asphalt gravel ice
  ground rust terrazzo bark water glass emissive.
- Props: `assets/models/<kit>/<name>.glb` (Kenney, CC0). Kits: city_kit_commercial/industrial/
  suburban/roads, nature_kit, castle_kit, pirate_kit, graveyard_kit, furniture_kit, survival_kit,
  fantasy_town_kit, modular_buildings, food_kit, car_kit, holiday_kit, blaster_kit,
  tower_defense_kit, mini_dungeon, hexagon_kit, platformer_kit, racing_kit, space_kit.
  Kenney kits are ~1 unit = 1 m at scale 1; buildings in city kits are small: scale 2–3.
- Layout (`layout`): `add_spawn_room(role, phase, center, yaw_deg, size)`, `control_points`,
  `capture_points`, `payload_path` (Curve3D) + `payload_checkpoints` (meters along path),
  `push_track`, `add_health_pack(pos, large)`, `kill_z`, `overview_camera`, `lanes`,
  `flank_routes`, `high_ground`, `chokepoints`, `perches`. Roles: escort/hybrid use
  `attack`/`defend` with phase = objective index; control/push use `a`/`b` (push: phase 1 =
  forward spawn).
- Every map needs: 3 lanes into every objective, at least one flank per objective, high ground
  with a counter-route, spawn-to-objective travel of 12–20 s for attackers and 6–12 s for
  defenders, health packs on flanks (never on the objective), props that tell a story.
- Register in `data/maps/<id>.tres` with `supported_modes`.

Validate: `tools/check.sh <id> <mode> 3600` — bots must reach the objective and score.

## VFX extensions

`src/vfx/hero_vfx/<hero>_vfx.gd` with `static func register() -> void` calling
`VfxLibrary.register_builder(&"id", func(lib: VfxLibrary) -> GPUParticles3D: ...)` or
`VfxLibrary.register_spawner(&"id", func(lib, pos, normal, color, attach): ...)` and
`DeployableVisuals.register(&"visual_id", func(kind, data, team, color, max_hp) -> Node3D: ...)`.
Use `lib.mesh_quad(size, VfxLibrary.soft_texture()|spark_texture()|ring_texture()|flash_texture())`.
